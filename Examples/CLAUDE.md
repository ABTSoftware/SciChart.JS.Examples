# SciChart.js Examples app

React app that hosts every SciChart.js example. Examples are discovered by a webpack context at
build time, so adding one is mostly metadata plus registration. The step-by-step walkthrough is in
[README-AddNewExample.md](README-AddNewExample.md); this file records the rules and traps that
guide does not cover.

## Anatomy of an example

`src/components/Examples/<Category>/<Group>/<Name>/`

| File                        | Purpose                                                                   |
| --------------------------- | ------------------------------------------------------------------------- |
| `index.tsx`                 | React component, usually just `<SciChartReact initChart={drawExample} />` |
| `drawExample.ts`            | the chart code, shared by every framework                                 |
| `drawExample.js`            | generated by `npm run compileVanillaExamples` - never hand-edit           |
| `exampleInfo.tsx`           | metadata: titles, SEO text, docs links, thumbnail                         |
| `<name>.jpg`                | thumbnail, 750x500, 20-50 KB                                              |
| `vanilla.ts` / `angular.ts` | optional standalone framework sources; newer examples omit them           |

Register it in two places, or it will not appear:

1. `npm run generateExamplePaths` writes `src/components/AppRouter/examplePaths.ts`
2. add `EXAMPLES_PAGES.<id>` to the menu arrays in `src/components/AppRouter/examples.ts`
   (an example may appear in several menus)

## frameworks: javascript, react AND angular are all required

`createFrameworkPropertyGetter` in `src/components/Examples/exampleInfoUtils.ts` looks the
requested framework up in `metadata.frameworks` and returns `""` when the key is missing - there is
no fallback to another framework. So an `exampleInfo.tsx` without an `angular` block renders the
Angular page with an empty `<h1>`, empty subtitle, empty browser tab title and empty meta
description, and the example appears untitled in the Angular menu. Same for a missing `javascript`
or `react` block.

Every field is required per framework; only `markdownContent` may be `null` (use that rather than
inventing framework-specific prose you cannot verify).

Before committing a new example:

```bash
for f in $(find src/components/Examples -name exampleInfo.tsx); do
    grep -q "angular:" "$f" || echo "missing angular: $f"
done
```

## Validating a change

```bash
npx tsc --noEmit -p tsconfig.json            # whole app, catches metadata typos
npm run compileVanillaExamples               # regenerate drawExample.js
npx prettier --write "<only the files you touched>"
npm run dev                                  # webpack-dev-server on :8080
```

Routes for eyeballing an example (`path` comes from `exampleInfo.tsx`):

-   `/iframe/<path>` - the chart alone, ideal for screenshots
-   `/<framework>/<path>` - the full page, e.g. `/angular/3d-model-chart`, which is where a missing
    framework block shows up as blank titles

The chart theme follows `localStorage["scichart-demo-theme"]` (`navy` | `dark` | `light`), set
before load. Thumbnails in the repo are captured in `navy`; without it the dev app renders light,
because `--bg-chart` and friends are only defined by the website shell, not by this app.

## Traps

-   **`generateExamplePaths` re-sorts the whole file** on some machines (collation differences) and
    drops the trailing comma, burying your one-line addition in noise. Check `git diff`; inserting
    the single path by hand is often cleaner.
-   **`compileVanillaExamples` re-emits unrelated `.js`** files whose sources drifted. Revert
    anything you did not mean to change.
-   **Keep prettier globs narrow.** A wide glob rewrites line endings on untouched files and they
    all show up as modified.
-   **`sitemap.xml` is not regenerated per example**; it is produced at deploy time, so a new
    example missing from it is expected.

## Charts3D/Basic3DChartTypes/Model3DChart

Loads a cooked 3D model into a `SciChart3DSurface`. Two things are worth knowing:

-   The model package is fetched from `https://stagingdemo.scichart.com/fileshare/F1CarAssets.web.pkg`
    (the engine appends `.web.pkg` to the package name, so the name may be an absolute URL). It is a
    ~28 MB staging asset and needs a production home before release; `scichart` does not ship it.
-   The entity has no load event, so the example polls `GetNodeHierarchyJson()` and calls
    `invalidateElement()` once the model arrives. Without that call a cached package can land before
    the first render pass and the scene stays empty.
-   `AstonMartin/mini-car.glb.twi` from the same package crashes the renderer with `[TSR FATAL]` on
    `scichart@6.0.0-alpha.196`; `aston.glb.twi` is used instead. Swap `modelFileName` back when the
    engine or the cooked asset is fixed.
